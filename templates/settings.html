Email

Set up an email integration in Home Assistant first (e.g. the SMTP integration, which creates a notify entity), then pick it here. Pistons that Send email route through it; the recipient comes from the piston. Home Assistant can't tell an email notifier from a Telegram or Slack one, so you choose which is email.

Playing media files

When a piston's Play track uses an old-school x-file-cifs://… network-share URL, PistonCore streams the file to your speakers itself — the share is read straight from the URL, nothing to set up here. Files kept in Home Assistant that use /local/… play through HA directly and don't need this at all. How this works →

Home Assistant configuration.yaml

HA only loads PistonCore's compiled automations if configuration.yaml has the PistonCore include lines. This checks the file (through the write target above) and shows you the exact changes before anything is touched. A timestamped backup is written first. Nothing is ever changed without your click.

    Piston variable helpers

    Some piston variables have to outlive a single automation run — a "switched on by hand" flag set in one place and checked back later is the usual case. Home Assistant's own automation variables can't do that, so PistonCore stores those in helper entities and needs one line in configuration.yaml pointing at the folder they live in. It's a packages folder, which merges with your configuration rather than replacing anything, so helpers you already define are untouched. This is checked automatically when PistonCore starts; the button is here for when the write target wasn't ready then. No Home Assistant restart.

    Translation data

    The compiler's knowledge of Home Assistant — every service and field name it uses — lives in editable data files, not in the program. This is where you can see which version is loaded, so you can tell whether an update actually landed. How updates work →
