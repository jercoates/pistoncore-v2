Updating the translation data

Everything PistonCore knows about Home Assistant — the name of every service it calls and every field it fills in — lives in data files, not inside the program. That's deliberate. Home Assistant renames things regularly, and when it does, the repair is a change to those files rather than a new version of PistonCore.

This page explains how those files get updated, how to tell whether an update actually arrived, and how to undo one. It's all on Settings → Translation data.

Two ways in — and you rarely need both

RouteWhat it updatesWhen you'd use it
Rebuild the container Everything — the program and the translation data. The data files refresh themselves on startup. When the program itself changed. This already covers the data, so there's no second step.
Check for official update Just the translation data. When a Home Assistant rename has been fixed and you want it now, without rebuilding anything.

If you rebuild, you do not also need to press the button — the rebuild already brought the data with it. The button exists so that people who don't rebuild containers can still get fixes.

How to tell an update actually landed

The Translation data panel shows a version code and when it was last checked. Reload Settings after an update and look at it. If it says Up to date with this build, the files match the program you're running.

It also lists anything that changed on the last restart, so an update isn't something you have to take on trust — you can see it.

Your own changes are kept

If you (or an AI acting for you) edit one of these files to fix something, that edit wins and survives future updates. Updates still flow into every part of the file you didn't touch. So fixing one command doesn't freeze the rest of the file in time.

Templates are the one exception. They're closer to program code than to data, so PistonCore can't safely merge someone else's changes into yours. If you've edited a template and a newer one ships, yours is kept and the panel says so, rather than silently overwriting your work.

Importing a fix someone shares

Import from a link takes a GitHub repo, a folder inside one, or a direct link to a single file. Paste it and press See what this would change — you get the list of files first, and nothing is written until you say so.

Be careful with templates from strangers. The .json files are data and are safe to import. Templates are not: they run as part of your compiler, so importing one means running someone else's work on your system. PistonCore warns you when an import includes a template but won't stop you — you're allowed to make that call, because being able to is the point.

Undoing an update

Nothing here is a one-way door. Whatever is in place gets saved before any change, and Go back offers three ways out:

Restore pointWhat it is
Shipped with this build The copies that came inside the version you're running. Needs no internet and can never go stale — the reliable floor if anything else goes wrong.
Latest official Fetched fresh from the PistonCore repo.
Previous version Whatever was in place immediately before the last change. This is the one-click undo, and it works in both directions — restore it, change your mind, restore again.

Older copies are also kept on disk under customize/.replaced, with the date in the filename.

If there's nobody left to update it

This is the reason all of the above exists. If PistonCore ever stops being maintained, the compiler is still repairable by whoever is using it: the names Home Assistant changed are in a file you can edit, an AI can be pointed at that file to make the change for you, and a fix that works can be shared with everyone else through a link. No release, and nobody upstream required.
